# Продукт и сценарии

Статус: первоначальная спецификация, 2026-11-06. Решения пользователя
отмечены явно; остальные детали предложены для первой версии.

## Назначение

Сервис помогает получать и проверять морфемные разборы слов. Единица работы —
словоформа из конкретной строки набора, а не уникальная строка текста во всей
системе. Одинаково написанные слова могут относиться к разным источникам,
омонимам или экспериментам и не объединяются автоматически.

Два подтверждённых режима проекта:

| Режим | Работа лексикографов | Результат |
| --- | --- | --- |
| `dictionary` | Общая редакция: участники редактируют одну текущую разметку | Проверенные разборы для словаря с историей изменений |
| `evaluation` | Каждому аннотатору выделена своя разметка того же материала | Независимые человеческие ответы, связанные с конкретным запуском модели |

В первой версии проект словаря объединяет партии пополнения — наборы слов.
Состав каждого импортированного набора неизменяем. Новые слова загружаются
следующей партией; выпуск словаря собирается из выбранных партий.
Сервис сохраняет идентификаторы и повторы, а не определяет самостоятельно,
являются ли две записи одной словарной статьёй. Автоматическое слияние
с внешним словарём и единый реестр лемм — отдельное дальнейшее развитие.

## Доступ и роли

Регистрация только по приглашению — решение владельца проекта.
Страницы входа и принятия приглашения доступны без авторизации. Наборы,
разборы, задания, исходные файлы и выгрузки доступны только участникам
соответствующего проекта. Участие в одном проекте не открывает другие.

| Роль | Полномочия |
| --- | --- |
| Администратор сервиса | Приглашения, блокировка аккаунтов, создание проектов, назначение руководителей, регистрация версий моделей, эксплуатация |
| Руководитель проекта | Участники из уже зарегистрированных пользователей, загрузки, запуски, назначение разметки, общие выгрузки и выбор редакции словаря |
| Лексикограф | Ввод слов и загрузка файлов в свой проект, запуск обработки своих наборов, правка общей редакции словаря или собственной разметки эксперимента, выгрузка доступных результатов |

В эксперименте чужие независимые разметки недоступны лексикографу, в том числе
через API, историю и выгрузку. Руководитель видит их для анализа; если он сам
аннотирует, этот расширенный доступ отмечается в протоколе эксперимента.
Администратор — доверенная эксплуатационная роль, его доступ не выдаётся
вместе с обычным участием в проекте.

Приглашение одноразовое, с ограниченным сроком действия и заранее выбранными
проектами/ролями. В базе хранится хеш случайного токена. Предлагаемый срок —
7 дней. Пользователь задаёт имя входа и пароль; email в первой версии
необязателен. Доставка ссылки выполняется администратором по существующему
каналу связи, поэтому запуск не зависит от SMTP. Наличие приглашения
подтверждает право регистрации, но само по себе не подтверждает email.
Администратор может выпустить одноразовую ссылку сброса пароля без получения
пароля пользователя. Блокировка аккаунта закрывает действующие сессии.

## Основной рабочий цикл

1. Пользователь входит и выбирает доступный проект.
2. Вводит слово или загружает файл. Одиночное слово создаёт набор из одной
   записи и проходит тот же путь хранения, разметки и экспорта.
3. Получает результат проверки файла: число строк, повторы, ошибки,
   примеры нормализации. Импорт с ошибками не запускает модель.
4. Подтверждает корректный импорт и выбирает зарегистрированную модель.
   Если модель одна, выбор уже заполнен. Параметры берутся из разрешённых
   настроек модели; произвольный Python-код или путь к весам в UI не вводятся.
5. Запускает обработку. Можно закрыть вкладку и вернуться позже.
   Появляются прогресс, число успешных записей и ошибки отдельных слов.
6. Автор набора открывает общую разметку либо собственную независимую
   разметку. Руководитель может назначить независимые разметки другим
   участникам. Обработка файла может ещё продолжаться: готовые записи
   уже доступны для правки.
7. Лексикограф выбирает предложенный вариант либо создаёт собственный,
   сохраняет черновик или подтверждает проверенный разбор.
8. Создаёт выгрузку: проверенный материал для словаря либо полный пакет
   для анализа модели, содержащий также статусы непроверенных записей.

## Редактор

На экране: слово, источник и его идентификатор, варианты модели, текущий
разбор, статус сохранения и навигация к следующей записи.

- Выбор варианта показывает морфемы и их типы, но не подтверждает запись
  без явного действия «Подтвердить».
- Пользователь ставит и убирает границы между символами, объединяет соседние
  морфемы и выбирает их тип из словаря меток проекта.
- Текст слова в редакторе неизменяем: морфемы всегда покрывают исходное
  нормализованное слово. Исправление опечатки означает новую входную запись
  с указанием причины; старую можно пропустить.
- Допустимы несколько корней, приставок и суффиксов. Правила числа и порядка
  морфем не выводятся из школьного разбора и не навязываются без согласования.
- Нулевые морфемы включаются только для согласованной схемы меток.
- Есть комментарий, сохранение черновика, подтверждение, пропуск с причиной,
  история и восстановление старого варианта как новой ревизии.
- Границы и типы доступны с клавиатуры; обозначения не зависят только от цвета.
  Перетаскивание может быть дополнительным способом ввода.
- При несохранённых изменениях переход предупреждает пользователя. Надпись
  «Сохранено» появляется только после ответа сервера. Автосохранение не входит
  в первый обязательный объём.

Рабочие фильтры: не проверено, черновик, подтверждено, пропущено, ошибка
инференса; поиск по слову и исходному идентификатору. Список постраничный.
Статус генерации и статус человеческой проверки показываются отдельно.

## Сохранение и совместная работа

`unreviewed` — ещё нет человеческой ревизии. Сохранённая ревизия имеет статус
`draft`, `confirmed` или `skipped`. Только явное подтверждение создаёт
проверенную запись; успешный инференс не делает её проверенной.

При двух открытых вкладках сервер проверяет номер версии. Если другой
пользователь успел изменить запись, сохранение возвращает конфликт и
показывает оба варианта. Последний запрос не затирает чужую правку.

Новая правка подтверждённой записи сохраняется как черновик и делает
текущую запись неподтверждённой до нового подтверждения. Прежние ревизии
и выпущенные выгрузки остаются доступны. Частично заполненный разбор можно
сохранить черновиком, но подтвердить — только после полной валидации.

## Границы первой версии

Включены приглашения, проекты и права, TXT/TSV, локальный инференс,
интерактивный редактор, история, оба режима разметки, надёжные задания,
выгрузки и базовая воспроизводимость эксперимента.

Не входят: обучение моделей на сервере, автоматическая публикация в чужие
словари, сложная процедура рецензирования и арбитража, несколько одновременно
действительных разборов одной записи, Excel/архивы, публичный API для внешних
клиентов и редактирование в реальном времени. Несколько допустимых разборов
в будущем потребуют отдельного формата эталонов; до этого неоднозначные
записи сопровождаются комментарием или пропускаются с причиной.
