# Интеграция сегментатора

Статус: предлагаемый контракт `v1`, 2026-11-06. Модель пока не предоставлена;
наличие батчей, нескольких вариантов, оценок и GPU не предполагается фактом.

## Граница адаптера

Сервис работает с нормализованными словоформами и типизированными сегментами.
Адаптер переводит вход в формат конкретной модели, запускает её и возвращает
единый результат. Внутренние метки, токенизация и способ декодирования модели
не должны попадать в код редактора.

Концептуальный Python-интерфейс, не готовая реализация:

```python
class SegmenterAdapter:
    def describe(self) -> ModelCapabilities: ...
    def load(self, artifact_path: str, config: dict) -> None: ...
    def predict(self, items: list[WordInput], options: PredictOptions) -> list[WordResult]: ...
    def close(self) -> None: ...
```

`describe()` сообщает версию контракта и адаптера, версию модели, допустимые
метки, поддержку `top_k`/батчей/seed/score, ограничения длины и алфавита,
необходимое устройство. Несовместимую модель нельзя выбрать для проекта.

Вызовы выполняются в постоянном локальном процессе с отдельным Python-
окружением. Координатор Django общается с ним через ограниченный по размеру
JSONL по stdin/stdout; stdout содержит только сообщения протокола, логи идут
в stderr. Запуск процесса выполняется по доверенной конфигурации, без shell
и без команд, составленных из пользовательского слова. Сетевой ML-сервис
не требуется. Если зависимости модели совместимы с приложением, оба
окружения можно собрать одним образом, сохранив разделение процессов.

## Запрос и ответ

Пример сообщения `predict`; один ответ соответствует одному `request_id`:

```json
{
  "protocol_version": "segmenter.v1",
  "request_id": "batch-example-1",
  "operation": "predict",
  "model_version_id": "model-example-1",
  "items": [{"item_id": "item-example-1", "word": "переписка"}],
  "options": {"top_k": 1, "seed": null}
}
```

```json
{
  "protocol_version": "segmenter.v1",
  "request_id": "batch-example-1",
  "results": [
    {
      "item_id": "item-example-1",
      "status": "ok",
      "candidates": [
        {
          "rank": 1,
          "score": null,
          "score_kind": null,
          "segments": [
            {"start": 0, "end": 4, "type": "PREFIX"},
            {"start": 4, "end": 7, "type": "ROOT"},
            {"start": 7, "end": 8, "type": "SUFFIX"},
            {"start": 8, "end": 9, "type": "ENDING"}
          ]
        }
      ],
      "error": null
    }
  ]
}
```

Ошибка слова: `status: "error"`, `candidates: []`,
`error: {"code": "WORD_TOO_LONG", "message": "...", "retryable": false}`.
Протокол также предусматривает операции `describe`, `load` и `shutdown`;
их схемы фиксируются при реализации адаптера.

Идентификатор связывает результат со входом; нельзя полагаться только
на порядок массива. Ответ содержит ровно один результат на входной
`item_id`. Пропущенные и дублированные идентификаторы — ошибка протокола.
Максимальные размер сообщения, время загрузки и время батча ограничены
конфигурацией, проверенной на реальной модели.

## Что сохраняется

- Исходный ответ адаптера до преобразования в предметные таблицы.
- Валидные кандидаты с исходными рангами, включая сведения об отклонённых
  невалидных вариантах. Ранги не перенумеровываются после фильтрации.
- Реальное число вариантов, seed и эффективные параметры; если модель
  поддерживает один разбор, нельзя имитировать несколько вариантов.
- Score только при наличии его определённой семантики. Log probability
  не показывается как процент уверенности и не сравнивается произвольно
  между моделями и словами.
- Параметры попытки, устройство и версия среды исполнения. При изменении
  батча после сбоя или повторном вычислении это также отражается в данных.

Невалидный вариант не предлагается лексикографу как готовый ответ. Если
все варианты невалидны, `RunItem` получает ошибку; ручная разметка слова
всё равно доступна. Нельзя автоматически исправлять ответ модели так,
чтобы исчезало различие между её ошибкой и человеческой правкой.

Адаптер возвращает координаты именно относительно `word_normalized`.
Если модель требует другое внутреннее представление, соответствие позиций
восстанавливает и проверяет адаптер. Скрытая замена `ё/е`, удаление ударений
или обрезка слова недопустимы; такое преобразование требует отдельного
явного и версионированного протокола входа.

## Жизненный цикл и ошибки

Веса загружаются один раз на процесс и переиспользуются. При переключении
версии текущий процесс завершается, затем загружается нужная модель; две
копии весов в памяти одновременно не требуются. Версия выбирается запуском
и не определяется меняющейся ссылкой `latest`.

Координатор следит за временем выполнения и может завершить зависший
дочерний процесс, продолжая обновлять аренду задания. После перезапуска
загружается та же закреплённая версия. Ошибка памяти может привести к
уменьшению батча в разрешённых пределах; изменение записывается в попытке.
Лимит попыток защищает от бесконечного повторения ошибочного задания.

Постоянные ошибки: недопустимый вход, неизвестная метка, несовместимый
контракт. Временные: авария процесса, тайм-аут, кратковременная недоступность
ресурсов. Ошибка загрузки весов видна как сбой модели, а не 100 000
независимых ошибок слов. Полные трассировки доступны администратору;
лексикографу показываются безопасный код и понятная причина.

## Реестр и воспроизводимость

Модели регистрирует администратор из локальных доверенных артефактов.
Пользователь загружает только данные для обработки. Веса, их загрузчики
и зависимости рассматриваются как исполняемый доверенный код.

`ModelVersion` фиксирует SHA-256 всех значимых файлов, конфигурацию,
версию адаптера, схему меток, lock-файл зависимостей или digest образа,
версию кода модели и сведения об устройстве. Созданная версия неизменяема;
обновлённые веса означают новую версию. Неактивную модель можно скрыть
из новых запусков, сохранив её исторические результаты.

Возможность повторить запуск и побитовая детерминированность — разные
свойства. Seed сохраняется, если поддерживается, но одинаковый seed
не гарантирует одинаковый результат на разных устройствах/библиотеках.
Исходные сохранённые ответы остаются основанием сравнения.

## Что проверить после получения модели

1. Как её загрузить и вызвать; Python/библиотеки/лицензия, размер артефактов.
2. Какие алфавиты, длины, регистр, ударения и дефисы поддерживаются.
3. Какие метки и специальные случаи реально выдаются, как кодируются границы.
4. Доступны ли несколько вариантов, батчи, score и управление случайностью.
5. Время холодного старта, скорость одиночного слова и батчей, RAM/VRAM.
6. Нужна ли GPU и есть ли пригодный CPU-режим; поведение при неверном входе.
7. Нужен ли контекст, лемма или часть речи сверх заявленного входа «слово».

Первую сквозную реализацию можно проверить на детерминированном заглушечном
адаптере, явно помеченном в интерфейсе и выгрузках как тестовый. Его разборы
не используются для лингвистических выводов.
