# Оценка качества и исследовательские данные

Статус: проект протокола, 2026-11-06.

## Независимость разметки

В режиме `evaluation` каждый участник работает в собственном `AnnotationSet`
и не видит ответы остальных. Результаты связываются с конкретным запуском
модели; одна правка не заменяет ответ другого аннотатора.

Первый пользовательский сценарий — исправление предложенных вариантов.
Его протокол называется `assisted`: аннотатор видел подсказки модели.
Такие данные полезны для анализа ошибок и трудоёмкости, но не являются
полностью независимым от модели эталоном. В частности, выбор первого
предложения может отражать влияние подсказки.

Будущий `blind`-режим скрывает кандидаты и оценки модели на сервере до
фиксации разметки, включая API, историю и экспорт. Простое сокрытие блока
на странице недостаточно. Это расширение не входит в обязательный первый
этап, но поле протокола вводится сразу. Независимость от других аннотаторов
и независимость от предсказаний модели — разные признаки.

## Два типа результата

1. **Разбор рабочего процесса:** какой процент ответов принят без правки,
   сколько изменено вручную, сколько пропущено и сколько осталось непроверенным.
   Эти показатели описывают взаимодействие лексикографа с конкретной моделью.
2. **Сравнение с зафиксированной разметкой:** новая модель получает те же
   неизменяемые входы, а её ответы сравниваются с выбранным снимком человеческих
   ревизий. Новый запуск не меняет ни снимок, ни исходный запуск, по которому
   этот снимок был создан.

В первой версии сохраняются и выгружаются все данные для обоих сценариев.
Расчёт метрик может первоначально выполняться отдельной локальной командой
по экспортному пакету; исследовательский dashboard не блокирует выпуск сервиса.

## Фиксация эталона

Руководитель явно выбирает наборы, коллекции и языки, аннотаторов,
подтверждённые ревизии, правила исключения и схему меток.
Снимок содержит точные `revision_id`.
Для сравнения моделей используется одна и та же выборка с одним и тем же
эталоном. Нельзя оценивать каждую модель только по словам, успешно обработанным
именно ею, и сравнивать полученные проценты как одинаковые условия.

Если у нескольких аннотаторов разные ответы, первая версия сохраняет их
отдельно: отчёт по каждому и долю расхождений. Автоматическое большинство
не объявляется правильным разбором. Для единого эталона руководитель выбирает
источник явно; дальнейшая процедура согласования и несколько допустимых
разборов требуют отдельного решения.

## Предлагаемые метрики

Пусть `N` — число записей с подтверждённым эталоном в фиксированной выборке.
Ошибки инференса и отсутствие кандидатов дают ноль для accuracy/recall;
их доля дополнительно сообщается. Человеческие черновики и пропуски не входят
в `N`, но их числа всегда показаны. При `N = 0` метрики не определены.

| Метрика | Определение |
| --- | --- |
| Exact match, top-1 | Доля из `N`, где кандидат исходного ранга 1 совпадает со всей последовательностью сегментов `(start, end, type)` |
| Recall@k | Доля из `N`, где эталон совпадает хотя бы с одним валидным кандидатом исходного ранга ≤ `k` |
| Boundary precision/recall/F1 | Микроусреднение по внутренним границам ненулевых сегментов, без 0 и конца слова |
| Labeled span precision/recall/F1 | Микроусреднение по точным тройкам `(start, end, type)` ненулевых морфем |
| Доля принятия | `accept_candidate / число подтверждённых записей`; отдельно по исходному рангу |
| Доля пропусков и ошибок | Отдельные категории относительно всех входных записей, с причинами |

Для множеств границ или сегментов считаются суммы `TP`, `FP`, `FN` по выборке.
`P = TP / (TP + FP)`, `R = TP / (TP + FN)`,
`F1 = 2TP / (2TP + FP + FN)`. Если знаменатель отдельной метрики равен нулю,
значение — `null` с пояснением, а не произвольные 0 или 1. При отсутствии
валидного top-1 множество предсказаний пустое. Поэтому boundary-метрика
сама по себе не выявляет все ошибки на словах без внутренних границ:
всегда приводятся также exact match и покрытие инференса.

Нулевые морфемы учитываются в exact match; для span-метрик по ним строится
отдельный отчёт, чтобы не смешивать явное отсутствие морфемы с границей
ненулевого сегмента. Невалидный первый кандидат не заменяется вторым при
вычислении top-1. Модель, выдающая меньше `k` кандидатов, оценивается по
реальному числу; дубликаты не создают дополнительного совпадения.

Одинаковые словоформы остаются отдельными наблюдениями по строкам исходного
набора, в том числе при совпадении написания в разных коллекциях или языках.
Отчёт явно указывает такое взвешивание. Дополнительный расчёт по
уникальным словоформам требует своего правила для омонимов и противоречащих
разборов и не выполняется скрытой дедупликацией.

Для смешанной выборки, кроме общего результата, отчёт показывает показатели
по коллекциям и языкам с отдельными знаменателями, в том числе группу
с неуказанным языком. Используются языки, зафиксированные при импорте.
`UNSUPPORTED_LANGUAGE` и `LANGUAGE_REQUIRED` считаются ошибками инференса
в соответствующих группах и не исключаются из общей выборки незаметно.
Сравнение моделей по языковому подмножеству допустимо при явно выбранном
одинаковом подмножестве для всех моделей.

## Что входит в отчёт

Версии входа, модели, адаптера, схемы меток и кода вычисления метрик;
эффективные параметры; `snapshot_id` эталона; протокол `assisted/blind`;
число входов, подтверждений, пропусков, ошибок, невалидных кандидатов;
значения метрик с явными знаменателями. Метрики для разных схем меток
не сравниваются без версионированного отображения между схемами.
В отчёт также входят идентификаторы и версии описаний коллекций, языки,
их источники и фильтры выборки; изменение языка словаря в текущем интерфейсе
не меняет уже рассчитанный эксперимент.

Время между открытием и сохранением страницы не является временем активной
разметки. В первой версии оно не выдаётся за надёжную оценку труда.
Если результаты позже используются для обучения, фиксируются разделение
train/dev/test и происхождение слов, чтобы тестовые исправления не попали
в обучение оцениваемой модели незаметно.
