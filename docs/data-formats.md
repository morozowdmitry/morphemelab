# Форматы данных

Статус: предложение `v1`, 2026-11-06. Форматы нужно согласовать до реализации
импорта. Примеры описывают структуру; это не эталон лингвистической разметки.

## Импорт

Общие правила: UTF-8, необязательный BOM только в начале файла, LF или CRLF.
Никакого автоматического угадывания кодировки или разделителя. Формат
пользователь выбирает явно; расширение служит подсказкой. Архивы и Excel
в первой версии не принимаются.

### TXT

Одно слово на физическую строку, без заголовка:

```text
переписка
лес
```

Пустые строки пропускаются с отчётом об их числе; исходные номера строк
сохраняются. Комментарии специальным синтаксисом не поддерживаются.
Табуляция и внутренние пробелы внутри поля слова считаются ошибкой.
Повторяющиеся слова допустимы и показываются в отчёте импорта.

### TSV

Первая строка — заголовок. Обязателен столбец `word`. Необязательные столбцы:
`external_id`, `lemma`, `pos`, `source`, `comment`. Неизвестные или повторные
заголовки отклоняются с понятным сообщением.

```text
external_id\tword\tlemma\tpos\tsource\tcomment
ex-001\tпереписка\tпереписка\tNOUN\tпример\t
ex-002\tлес\tлес\tNOUN\tпример\t
```

Здесь `\t` обозначает табуляцию; в [реальном примере](examples/words.tsv)
использованы символы табуляции. Все столбцы — строки, пустое необязательное
поле означает отсутствие значения. Поля не могут содержать перевод строки
или табуляцию; кавычки не включают многострочный CSV-режим. Число полей
в каждой непустой строке должно совпадать с заголовком.

`external_id` сохраняется строкой, включая ведущие нули. Непустые значения
уникальны в пределах набора. `lemma` и `pos` пока являются метаданными;
они не передаются модели, принимающей только слово.

Ошибка любой содержательной строки блокирует подтверждение всего импорта.
Отчёт содержит номера строк и причины; исходный файл сохраняется. Пустой
после проверки набор отклоняется. При большом числе ошибок экран показывает
первые 100 и общее число, полный отчёт доступен отдельным закрытым файлом.

## Нормализация и индексы

`normalization_version = nfc-trim-v1`:

1. Декодировать UTF-8 без замены ошибочных байтов.
2. Удалить разделитель строк; для слова обрезать внешние Unicode-пробелы.
3. Привести слово к Unicode NFC.
4. Проверить непустоту, длину и отсутствие внутренних пробелов/управляющих
   символов; допустимые алфавиты и дефисы дополнительно проверяет адаптер.

Не менять регистр, `ё` на `е`, дефисы и ударения автоматически. Каждое
изменение нормализацией отражается в предпросмотре. Исходное поле слова
и исходные байты файла сохраняются отдельно от нормализованного текста.
Версия нормализации входит в хеш набора и манифест запуска.

Границы морфем — полуинтервалы `[start, end)` в **кодовых точках Unicode**
нормализованного слова. Это не байты UTF-8 и не индексы UTF-16 JavaScript.
Клиент строит отображение позиций через массив кодовых точек, например
`Array.from(word)`, и отдельно учитывает отображаемые графемные кластеры.
Граница внутри графемного кластера запрещена, в частности между буквой
и присоединённым знаком ударения. Сервер и клиент должны использовать
согласованные правила определения таких границ.

## Разбор

Внутренний формат сегмента:

```json
{
  "start": 0,
  "end": 4,
  "type": "PREFIX"
}
```

Текст сегмента вычисляется срезом нормализованного слова и не хранится
вторым независимым значением. Иллюстрация полного разбора:

```json
{
  "schema_version": "segmentation.v1",
  "label_schema_version": "ru-proposed-v1",
  "word": "переписка",
  "segments": [
    {"start": 0, "end": 4, "type": "PREFIX"},
    {"start": 4, "end": 7, "type": "ROOT"},
    {"start": 7, "end": 8, "type": "SUFFIX"},
    {"start": 8, "end": 9, "type": "ENDING"}
  ]
}
```

Предварительный инвентарь меток:

| Код | Обозначение в интерфейсе |
| --- | --- |
| `PREFIX` | Приставка |
| `ROOT` | Корень |
| `SUFFIX` | Суффикс |
| `ENDING` | Окончание |
| `POSTFIX` | Постфикс |
| `INTERFIX` | Интерфикс |

Этот список не объявляется универсальной лингвистической схемой.
Другие типы, обработка дефиса, соединительных элементов, нулевых морфем
и спорных случаев согласуются с лексикографами. `LabelSchema` версионируется;
существующие разборы не меняют смысл после добавления новой схемы.
Неизвестная метка модели вызывает ошибку отображения меток, а не молчаливую
замену на `ROOT` или `OTHER`.

Правила для подтверждённого разбора:

- индексы целые, `0 ≤ start ≤ end ≤ длина слова`;
- ненулевые сегменты идут по порядку, без пробелов и пересечений, покрывают
  всё слово от `0` до его длины;
- тип каждого сегмента входит в закреплённую схему; в черновике допустим
  `type: null`, в подтверждённом разборе — нет;
- пустая последовательность недопустима для непустого слова;
- нулевые сегменты разрешены только явно разрешённым типам на существующей
  границе, не участвуют в покрытии, не дублируются с теми же координатами
  и типом. Их порядок задаётся позицией границы и порядком типов в схеме.

Например, если схема разрешает нулевое окончание, слово `лес` может иметь
`ROOT [0,3)` и `ENDING [3,3)`. Отсутствие окончания и явное нулевое окончание
не равнозначны. Контракт не поддерживает разрывные морфемы и алломорфные
представления, не совпадающие с подстрокой слова; если модель или словарь
их требуют, схему нужно расширить до реализации редактора.

## Экспорт

Каждая выгрузка имеет версию схемы, `snapshot_id`, время создания, фильтры,
количества включённых и исключённых записей и SHA-256 итоговых файлов.
Файлы строятся по сохранённому снимку, а не по текущему состоянию интерфейса.

### Для словаря

`dictionary.v1.jsonl`: одна JSON-запись на текущую **подтверждённую** запись
выбранных общих редакций. Сохраняются `dataset_id`, `item_id`, `external_id`,
слово, сегменты, версия меток, `revision_id`, автор и время подтверждения.
Непроверенные, черновики и пропуски исключаются; их числа явно указаны
в манифесте. Пользователь может потребовать полный выпуск: тогда наличие
неподтверждённых записей блокирует экспорт вместо выпуска неполного словаря.

Для просмотра предусмотрен TSV с полями `dataset_id`, `item_id`,
`external_id`, `word`, `segments_json`, `revision_id`. Однозначное JSON-поле
сохраняет нулевые морфемы; строка вроде `пере:PREFIX/пис:ROOT/...` может быть
добавлена для чтения, но не является основным обменным представлением.
TSV для таблиц защищает текстовые ячейки от интерпретации как формул;
такая копия помечается как представление для просмотра. JSONL сохраняет
исходные значения без преобразования для электронных таблиц.

### Для оценки модели

Пакет `evaluation.v1` состоит из `manifest.json` и `records.jsonl`.
Включаются все выбранные слова, включая ошибки инференса и непроверенные
записи. Одна строка JSONL соответствует паре «входная запись, набор разметки»;
для нескольких аннотаторов у слова будет несколько строк.

```json
{
  "schema_version": "evaluation-record.v1",
  "item_id": "item-example-1",
  "external_id": "ex-001",
  "word_original": "переписка",
  "word": "переписка",
  "run_id": "run-example-1",
  "prediction_status": "succeeded",
  "candidates": [
    {
      "id": "candidate-example-1",
      "rank": 1,
      "score": null,
      "segments": [
        {"start": 0, "end": 4, "type": "PREFIX"},
        {"start": 4, "end": 7, "type": "ROOT"},
        {"start": 7, "end": 8, "type": "SUFFIX"},
        {"start": 8, "end": 9, "type": "ENDING"}
      ]
    }
  ],
  "annotation_set_id": "annotation-example-1",
  "annotation_protocol": "assisted",
  "review": {
    "revision_id": "revision-example-1",
    "author_id": "user-example-1",
    "status": "confirmed",
    "method": "accept_candidate",
    "source_candidate_id": "candidate-example-1",
    "segments": [
      {"start": 0, "end": 4, "type": "PREFIX"},
      {"start": 4, "end": 7, "type": "ROOT"},
      {"start": 7, "end": 8, "type": "SUFFIX"},
      {"start": 8, "end": 9, "type": "ENDING"}
    ]
  }
}
```

Идентификаторы здесь условные; в реализации используются UUID.
Для непроверенной записи `review: null`; для пропуска хранится причина,
а `segments: null`. Для ошибки модели `candidates: []` и диагностический код.
Ошибки и пропуски не превращаются в пустой «правильный разбор».

Манифест содержит версии и хеши входа, нормализации, меток, модели, адаптера,
приложения, эффективные параметры запуска, протокол разметки и критерии
выборки. Имена и email участников в исследовательскую выгрузку по умолчанию
не включаются: используются устойчивые идентификаторы. Экспорт результатов
в первой версии не означает поддержку их обратного импорта.
